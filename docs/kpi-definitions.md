# KPI定義

各指標の **計算式・分母・データ元** を定義します。画面・SQL・Python・Tableauはすべてこの定義に従います。

> **実装状況（Phase 3）**: MJ Social の投稿単位の指標は SQL ビュー `social_post_snapshot_kpis` / `social_post_kpis` で、MJ Marketing の集客ファネル（問い合わせ〜入会・CPA・CAC）は SQL 関数 `marketing_funnel()` で実装済みです。計算式の正式な定義は `shared/kpi-catalog.json` にあり、この文書と一致させています。**実際の事業データではまだ検証していません**。売上・利益・ROAS（MJ Finance / Analytics）は **未実装** です。
>
> **SNS指標と経営指標の区別**: SNS指標はプラットフォームの集計値に基づき「どの投稿が見られ反応されたか」を表します。経営指標は記録した問い合わせ・入会・売上・費用に基づきます。SNS指標から入会数を推定しません（詳細は `docs/decision-support-design.md`）。

## 共通ルール

1. **比率の分母が0、または分子・分母のどちらかが実測でない場合は「計算不能」**（`null` / `NaN`）とし、0%と表示しない。
2. **累積指標は投稿ごとに最新の記録を使う**（`social_post_latest_metric_values`）。複数時点を合計しない。
3. **期間は日本時間（Asia/Tokyo）で区切る**。
4. **全件ではなく「指標が実測の投稿のみ」を分母にする場合は、対象件数（n）を必ず併記する**。
5. 平均だけでなく **中央値** を併記する（SNSは一部の投稿だけが大きく伸びる分布になりやすく、平均が引っ張られるため）。
6. **率は同じ記録時点の値どうしで計算する**。投稿の「最新」の率は、最新のスナップショット1件の値で計算する。
7. グループ比較の信頼度は、**最も件数の少ないグループのn** で判定する（`comparisonLevel`）。

## MJ Social（Phase 2）

| 指標 | 計算式 | 分母 | 注意 |
|---|---|---|---|
| リーチ率 | リーチ数 ÷ フォロワー数（記録時点） | フォロワー数 | フォロワー外に届いた分も含むため100%を超えることがある |
| **エンゲージメント率（リーチ基準）** ★既定 | (いいね + コメント + 保存 + シェア) ÷ リーチ数 | リーチ数 | 「届いた人のうち反応した割合」。Instagramとの比較の基本 |
| エンゲージメント率（再生基準） | (いいね + コメント + 保存 + シェア) ÷ 再生数 | 再生数 | 1人が複数回再生すると下がる。TikTokで補助的に使う |
| 保存率 | 保存数 ÷ リーチ数 | リーチ数 | 「後で見返したい」価値の指標。教育系コンテンツで重要 |
| シェア率 | シェア数 ÷ リーチ数 | リーチ数 | |
| プロフィール遷移率 | プロフィールアクセス ÷ リーチ数 | リーチ数 | 集客ファネルの入口 |
| リンククリック率 | リンククリック ÷ プロフィールアクセス | プロフィールアクセス | プラットフォームにより未対応のことがある |
| フォロワー増加数 | 投稿ごとの記録値、またはアカウント単位の差分 | — | 投稿単位で取れない場合は「非対応」 |
| 制作効率 | リーチ数 ÷ 制作時間（時間） | 制作時間 | 制作時間が未入力の投稿は除外し、件数を併記 |
| 成長推移 | 公開からの経過時間ごとの値 | — | 24h / 72h / 7日後など。記録タイミングがずれる場合は最も近い記録を使い、ずれ幅を表示 |

**エンゲージメントの合計項目のいずれかが「未取得・非対応」の場合**、その投稿のエンゲージメント率は計算不能とします（一部の項目だけで計算すると、プラットフォーム間で比較できなくなるため）。

## MJ Marketing（Phase 3・実装済み）

件数は `marketing_funnel(org, from, to, group)` が数え、率・単価は画面（`src/lib/marketing.ts` の `funnelRates`）が件数どうしを割ります。

| 指標 | 計算式 | 分母・単位 | 注意 |
|---|---|---|---|
| 問い合わせ数 | 期間内の `inquiries` 件数 | 件 | `inquired_at` 基準 |
| 体験申込率 | 体験申込があった問い合わせ数 ÷ 問い合わせ数 | 問い合わせ数 | 体験は振替で複数行ありうるため `distinct inquiry_id` |
| 体験参加率 | 体験に参加した問い合わせ数 ÷ 体験申込があった問い合わせ数 | 体験申込数 | キャンセル・欠席は参加に含めない |
| 入会転換率（体験→入会） | 入会した問い合わせ数 ÷ 体験に参加した問い合わせ数 | 体験参加数 | 体験に参加せず入会した人も分子に入るため、100%を超えることがある |
| 入会転換率（問い合わせ→入会） | 入会した問い合わせ数 ÷ 問い合わせ数 | 問い合わせ数 | |
| 問い合わせ獲得単価（CPA） | マーケティング費用 ÷ 問い合わせ数 | 問い合わせ数 | 期間・チャネルを揃える。費用が未記録・権限なしなら計算不能（0円とみなさない） |
| 顧客獲得単価（CAC） | マーケティング費用 ÷ 新規入会数 | 入会数 | 制作の人件費を含めるかを明記（既定: `marketing_costs` のみ） |
| 問い合わせ→入会日数 | 入会日 − 問い合わせ日 | 日 | 中央値で表示。入会していない問い合わせは除外 |

**コホートの考え方**: 率を計算するときは「同じ期間に問い合わせた人のうち、その後入会した人」で数えます（問い合わせ月コホート）。「今月の入会数 ÷ 今月の問い合わせ数」は、別の人を割っているため使いません。直近の問い合わせはまだ入会判断前なので、成熟していない期間であることを表示します。

**費用の期間**: 費用は `occurred_on` が期間内のものを合計します（問い合わせ日と同じ期間）。広告を出した月と問い合わせが来た月がずれる場合があるため、短い期間のCPA・CACは振れやすくなります。チャネル別の費用は、費用にチャネルを付けた分だけが入ります。

**投稿の貢献について**: 問い合わせと投稿の紐づけは `attribution` で確度を区別します。`tracked_link` 以外の紐づけは「参考値」と表示し、投稿が入会に貢献したと断定しません。

## MJ Finance / Analytics（Phase 4）

| 指標 | 計算式 | 注意 |
|---|---|---|
| 月次売上 | `revenue_transactions.amount_jpy` の月合計 | 返金（マイナス）を含む |
| 月次費用 | `expense_transactions.amount_jpy` の月合計 | |
| 月次営業利益 | 月次売上 − 月次費用 | |
| 営業利益率 | 月次営業利益 ÷ 月次売上 | 売上0なら計算不能 |
| 広告費比率 | マーケティング費用 ÷ 月次売上 | |
| 在籍生徒数 | 月末時点で `status='active'` の契約がある生徒数 | |
| 退会率（月次） | 当月退会者数 ÷ 月初の在籍生徒数 | |
| 講師稼働時間 | `staff_work_logs.minutes` の合計 ÷ 60 | 種類別（授業・準備・SNS制作・事務） |
| 見込み人件費 | 稼働時間 × 時給 | 損益には使わない（実額は費用台帳） |
