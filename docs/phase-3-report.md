## 2. 採用した技術と理由

- **SQL関数 `marketing_funnel()`**: 期間と切り口を引数で受け取り、件数だけを返す。率は画面で件数どうしを割るため、分母0の「計算不能」を一か所（`src/lib/marketing.ts`）で扱える。呼び出したユーザーの権限（RLS）で動く。
- **RPC関数 `record_enrollment()`**: 生徒と契約を1トランザクションで作る。途中で失敗したら両方とも作らない。
- **ビュー `inquiry_pipeline`**: 一覧と詳細に必要な名前・件数・進捗を1か所で計算する。閲覧者には入会情報を返さない。
- **費用は既存の費用台帳（`expense_transactions`）に保存**: マーケティング費用はビュー `marketing_costs` で読むだけにし、二重計上を防ぐ（Phase 1 の設計どおり）。

## 3. データの処理方法

```
問い合わせ登録（流入URL・追跡コード → チャネル・投稿・確度）
   ▼
inquiries ── trial_lessons（振替で複数行） ── enrollments（1問い合わせ1件、DBが保証）
   │                                              ▲
   │                                   record_enrollment()（生徒 + 契約）
   ▼
marketing_funnel(org, from, to, group)
   … 期間内（日本時間の日付）に問い合わせた人を、その後の到達段階で数える
   … 体験は問い合わせごとに 0/1（行数で数えない）
   … 費用は marketing_costs（広告費・キャンペーン費・制作外注費）の期間内合計
   ▼
画面: 率・CPA・CAC を計算（分母0・費用なしは「計算不能」「費用未記録」）
```

## 4. 指標の意味と計算式（経営指標）

| 指標 | 計算式 | 分母 |
|---|---|---|
| 問い合わせ数 | 期間内の問い合わせ件数 | — |
| 体験申込率 | 体験申込があった問い合わせ ÷ 問い合わせ | 問い合わせ数 |
| 体験参加率 | 体験に参加した問い合わせ ÷ 体験申込があった問い合わせ | 体験申込数 |
| 入会転換率（体験→入会） | 入会 ÷ 体験に参加した問い合わせ | 体験参加数 |
| 入会転換率（問い合わせ→入会） | 入会 ÷ 問い合わせ | 問い合わせ数 |
| CPA | 集客費用 ÷ 問い合わせ数 | 問い合わせ数 |
| CAC | 集客費用 ÷ 入会数 | 入会数 |
| 入会までの日数 | 入会日 − 問い合わせ日 の中央値 | 入会した人 |

- **コホート**: 「今月の入会 ÷ 今月の問い合わせ」ではなく、「期間内に問い合わせた人のうち、その後入会した人」で数えます。期間が直近30日を含む場合は「成熟していない期間」と表示します。
- **費用**: 人件費は含めません。費用が未記録なら0円とみなさず「費用未記録」、権限がなければ「権限なし」と表示します。
- **投稿の貢献**: 「追跡リンク」以外の紐づけは参考値です。チャネル間・投稿間の差は相関であり、その投稿やチャネルが入会の原因だとは言えません。
