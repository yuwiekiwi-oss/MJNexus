# 意思決定ログ

技術・設計の判断とその理由を記録します（ADR: Architecture Decision Record の簡易版）。

## 2026-11-04 Phase 1

### D-001 フロントエンドは Vite + React（Next.js不使用）
- **理由**: 仕様の指定。管理画面はSEOやサーバーレンダリングが不要で、静的SPAで十分。Cloudflare Pagesで配信できる。

### D-002 shadcn/ui は手書きで導入
- **状況**: 開発環境のネットワーク制限で `npx shadcn add` がレジストリ（ui.shadcn.com）に接続できなかった。
- **判断**: shadcn/ui と同じ構成（Radix UI + class-variance-authority + Tailwind、`components.json`、`src/components/ui/`）で必要な部品を手書きした。
- **影響**: 今後、ネットワークが使える環境では `npx shadcn add <component>` でそのまま追加できる。

### D-003 マルチテナント構造（organization_id）を最初から入れる
- **理由**: 現時点はスクール1つだが、RLSの判定単位として「組織への所属」があると権限設計が単純になる。後から全テーブルに列を足すより安い。
- **代償**: 全テーブルに `organization_id` が必要。複合外部キーで組織間の混在を防ぐ。

### D-004 SNS指標は縦持ち（スナップショット × 指標）
- **理由**: プラットフォームによって取得できる指標が異なり、さらに「未取得・非対応・実測0」を区別する必要がある。横持ち（列ごと）だと状態列が指標数だけ必要になる。
- **代償**: 画面表示や分析では横に並べ直す（ピボット）処理が必要。ビューとPythonで用意する。

### D-005 費用は単一の台帳 + マーケティング費用はビュー
- **理由**: 仕様の `marketing_costs` を独立テーブルにすると、広告費を「費用」と「マーケ費用」に二重入力するリスクがある。
- **判断**: `expense_transactions` に一本化し、`marketing_costs` は `category in ('ad_spend','campaign','content_production')` のビューにした。

### D-006 個人情報は別テーブル・admin以上のみ
- **理由**: 未成年の情報を扱う。分析に必要なのは件数や日付であり、氏名・連絡先は不要。
- **判断**: 問い合わせ・生徒の本体には個人情報を置かず、連絡先を `inquiry_contacts` / `student_guardians` に分離。生徒は呼び名と学年のみ。

### D-007 招待制（新規登録無効）
- **理由**: 誰でもアカウントを作れると、組織を作成してシステムを使えてしまう。業務システムとして利用者を限定する。

### D-008 DBテストは素のPostgreSQL + Supabase互換シム
- **理由**: Supabase CLI のローカル環境はDockerが必要。CIや手元で軽く回せるよう、`auth.uid()` とロールだけを模倣したシムでマイグレーションとRLSを検証する。
- **限界**: Supabase固有の機能（Storage・Realtime等）は検証できない。接続後に Supabase のステージング環境でも確認する。

### D-009 Supabase未接続でも画面を確認できる
- **理由**: Supabase の準備前でもデザイン・レイアウトを確認できるようにする。
- **安全策**: 未接続モードでは常に警告バナーを出し、データを一切扱わず、サンプル値も表示しない。

### D-011 率は同じ記録時点の値で計算する（2026-11-05）
- **理由**: 指標ごとに最新値を取ると、時点のずれた分子・分母を割ってしまう。
- **判断**: `social_post_kpis` は最新スナップショット1件で率を計算。指標ごとの最新値ビューは個別値の確認用に残す。

### D-012 グループ比較は記述統計（中央値）まで、検定は Phase 4
- **理由**: 開業準備段階でデータが少ない。各グループの件数と信頼度を表示し、n≥30 未満では結論を出さない。

### D-013 SNS分析と経営分析を画面・コード・KPIカタログで分ける
- **理由**: SNSの集計値と、識別できる問い合わせ・入会のイベントは性質が違う。混ぜると「再生数が多い＝集客に効いた」と誤解しやすい。
- **判断**: KPIカタログに `domain`（social / business）を持たせ、画面に「SNS指標」「経営指標」のラベルを常に表示する。

### D-014 デモ表示（サンプルデータ）は別ビルド
- **理由**: Supabase接続前に画面を確認したいという要望。
- **安全策**: `VITE_DEMO_MODE=true` のときだけ動的 import で読み込み、通常ビルドには含まれないことを確認済み。全タイトルに【サンプル】を付け、上部に「デモ表示・架空のデータ」と表示し、書き込みはすべて拒否する。

### D-015 追跡コードと施策テーブルを Phase 2 で先に作る
- **理由**: 投稿と問い合わせを確度高くつなぐには、投稿時点で追跡リンクを使い始める必要がある。施策の記録も、最初の施策の前に受け皿が要る。

### D-010 TypeScript 7 / Vite 8 / React Router 8 / Tailwind v4
- **理由**: 2026年11月時点の各ツールの最新安定版を `npm create vite` の既定構成から採用。仕様の技術スタックから変更はない。
- **注意**: Lintは Vite の既定テンプレートに含まれる oxlint を使用（ESLintより高速。仕様に指定がないため既定のまま）。

### D-016 ファネルはSQL関数で件数を数え、率は画面で割る（2026-11-05, Phase 3）
- **理由**: 期間・切り口を引数で受け取る集計はビューより関数が扱いやすい。件数（分子・分母）をそのまま返せば、画面・Python・AIが同じ件数から率を計算でき、分母0の「計算不能」も各所で同じ扱いにできる。
- **判断**: `marketing_funnel(org, from, to, group)` は security invoker（呼び出したユーザーのRLSで読む）。editor 未満は拒否する（閲覧者は入会を読めず「入会0件」と誤表示されるため）。費用は admin 以上のみ返し、権限なし・未記録はどちらも NULL で `cost_visible` で区別する。

### D-017 体験申込は「問い合わせ単位」で数える
- **理由**: 振替で体験が2行になっても、申込した人は1人。`exists` で問い合わせごとに0/1にし、行数で数えない。

### D-018 入会の記録は RPC で生徒と契約を同時に作る
- **理由**: 生徒だけ・契約だけが残る中途半端な状態を作らない。入会日が問い合わせ日より前、他組織のコース、同じ問い合わせからの2件目の入会はDBが拒否する。

### D-019 閲覧者に入会状況を見せない（「権限なし」と表示）
- **理由**: 生徒（未成年）の情報のため、入会は editor 以上。ビュー `inquiry_pipeline` は閲覧者に `stage = NULL` を返し、画面は「未入会」ではなく「権限なし」と表示する。

### D-020 投稿との紐づけは確度別に分け、追跡リンク以外は参考値
- **理由**: 「Instagramで見た」という回答と、追跡コード付きリンク経由とは確かさが違う。「追跡リンク」は追跡コードで投稿を照合できた場合だけ選べるようにし、ファネルには確度別の切り口を用意する。
- **限界**: Webサイトの問い合わせフォームが流入URL（UTM）を自動で残す仕組みはサイト側の対応が必要で、MJ Nexus の範囲外（未実装）。現状はスタッフが流入URLか追跡コードを入力する。

### D-021 機能を集客（問い合わせ〜入会・集客費用）だけに絞る（2026-11-05）
- **理由**: 最初に多くの機能を一度に依頼したが、実際に必要なのは集客の記録と分析だけだった。使わない機能は保守の負担になり、画面も分かりにくくする。
- **判断**: Social・Content Planner・SNSダッシュボード・CSV、施策・AI提案のテーブル、Overview、Coming Soon のメニュー（Analytics・AI Insights・Finance・Students・Staff・Knowledge・Learning）を削除した。DBも Supabase 未接続で本番データがないため、マイグレーションから該当テーブル（SNS・企画・売上・講師・保護者連絡先・AIログ・施策）を取り除いた。必要だと分かった機能は、その時点で追加する。
- **影響**: 問い合わせと投稿の紐づけ（追跡コード・投稿のテーマ別／プラットフォーム別ファネル）も削除。きっかけは UTM とチャネル・確度で記録する。以前の機能は git の履歴（コミット `8bee149` 以前）に残っている。
- **上の記録について**: D-011〜D-015 と D-020 の一部は削除した機能に関するもので、履歴として残している。
