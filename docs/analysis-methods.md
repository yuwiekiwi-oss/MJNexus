# 分析手法

データ量に応じて、適用してよい手法を段階的に増やします。**統計的に妥当でない段階で高度な分析を使わない** ことが原則です。

> **実装状況**: Phase 1 ではデータ品質の確認（`coverage_report`）とサンプル数による分析レベル判定（`sample_size_level`）のみ実装済み。統計手法は Phase 4 で実装します。

## 分析の前に必ず確認すること

`analytics/mj_analytics/data_quality.py` の `coverage_report()` で次を確認し、結果と一緒に表示します。

- **収集期間**: いつからいつまでのデータか
- **サンプル数（n）**: 何件のデータか
- **欠損状況**: 指標ごとに何%が未取得・非対応か

## サンプル数と分析レベル

| n | レベル | できること | やらないこと |
|---|---|---|---|
| 0 | none | 「データがない」と伝える | 推測で埋める |
| 1〜9 | anecdotal（事例） | 個別の投稿を並べて見る | 平均の比較、「〜の方が良い」という結論 |
| 10〜29 | descriptive（記述） | 中央値・範囲・分布の可視化 | 有意差の主張 |
| 30〜 | inferential（推測） | 信頼区間、仮説検定、回帰分析 | 因果の断定（実験でない限り） |

閾値は「過信を防ぐための安全側の目安」で、厳密な統計的基準ではありません。比較するグループそれぞれのnで判定します（例: テーマAが40件でもテーマBが5件なら、比較はanecdotal）。

## 手法（Phase 4 以降）

| 手法 | 用途 | ライブラリ | 用語の説明 |
|---|---|---|---|
| 記述統計 | 平均・中央値・四分位 | pandas | データの要約。まずはこれ |
| 時系列の可視化 | 投稿後の伸び、月次推移 | Recharts / pandas | |
| 信頼区間 | 率の不確実性の幅 | statsmodels（Wilson区間） | 「真の値がおそらくこの範囲にある」幅。nが小さいほど広い |
| 仮説検定 | 2グループの率・平均の差 | SciPy（Fisherの正確検定、Mann-Whitney U検定） | 「差が偶然で説明できるか」を確かめる。p値は効果の大きさではない |
| 回帰分析 | 複数要因の関係 | statsmodels | 投稿時間・テーマ・形式を同時に考慮する。nが十分なときのみ |
| コホート分析 | 問い合わせ月ごとの入会率 | SQL（CTE + ウィンドウ関数） | 「同じ時期に始めた人」を追いかける |
| 施策前後の比較 | 施策の効果の目安 | pandas | 季節性・他施策の影響を受けるため、因果とは言えない |

SNSの指標は外れ値が多いため、平均の差より **中央値とノンパラメトリック検定**（分布の形を仮定しない検定）を優先します。

## 因果と相関

- 投稿データやファネルデータは **観察データ** であり、示せるのは基本的に相関です。
- 「テーマAの投稿後に問い合わせが増えた」は、同時期の他の要因（季節、広告、口コミ）でも説明できます。
- 因果を主張するには、ABテストのような比較実験が必要です。現時点では「〜と関係がある可能性」「検証するには〜」と表現します。
- AI Insights（Phase 5）の回答も、このルールに従って事実と仮説を分けます。

## 実行方法

```bash
cd analytics
pip install -r requirements.txt
python -m pytest
```

まずはローカル実行・バッチ処理を想定しています。定期実行が必要になった場合は、GitHub Actions のスケジュール実行（サーバー管理不要）で読み取り専用の接続情報を使う方法を検討します。
